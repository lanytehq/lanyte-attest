# Release Notes — v0.1.0

**Release Date**: 2026-05-22
**Status**: First public release. Session attestation CLI + library; foundational CRT-012 surface.

## Summary

`lanyte-attest` is the session-attestation primitive for supervised
Lanyte agent sessions. It mints signed JWTs covering a `(role, scope,
supervisor, session)` tuple, verifies them locally against a trusted
issuer config, and tracks session lifecycle (active / ended / revoked)
in a local sqlite database. Downstream tools — starting with
`stashvoy` — consume the shared `verify` library surface rather than
re-implementing token verification.

v0.1.0 is the first release. It locks in the foundational CRT-012
surface, the canonical license-text restoration, the dependency
license-policy baseline, and the full manual-signing release
infrastructure (Makefile + scripts + `RELEASE_CHECKLIST.md`). Signing
keys themselves are not yet provisioned at the v0.1.0 cut — the
machinery is in place to sign the binaries once the lanytehq
minisign + GPG keypair lands, and `keys/expected-fingerprints.txt`
documents that pending state explicitly so verification can never
silently pass against an un-pinned key.

## What's New

### Session attestation CLI

```text
lanyte-attest keygen [--output <dir>] [--issuer <instance>]
lanyte-attest begin --role <role> --scope <scope> [--ttl <duration>] [--supervisor <handle>] [--emit-env | -- <child-cmd>]
lanyte-attest verify <token>
lanyte-attest end
lanyte-attest revoke <jti>
```

- `keygen` generates an Ed25519 signing key, encrypts the 32-byte
  seed with `seclusor-crypto v0.1.1`, and writes key material under
  the attest root (`signing-key.pub` for the public key as base64;
  `signing-key.age` for the encrypted private key).
- `begin` mints a token and records session state. With `--emit-env`,
  prints shell export code; otherwise execs a child command with
  `LANYTE_SESSION_TOKEN` set in the environment.
- `verify` validates JWT shape, Ed25519 signature, expiry, issuer,
  and optional role/scope expectations, then emits claims as JSON
  on stdout. Suitable for both ad-hoc inspection and programmatic
  consumer-side gating.
- `end` and `revoke` transition tracked sessions in sqlite through a
  shared canonical status path that `verify` reads — a single source
  of truth for "is this session still attested."

### Library surface (`verify`-only feature)

`cargo check --no-default-features --features verify` is the intended
downstream-consumer boundary. `stashvoy` consumes this surface
directly rather than copying token-verification logic, so the
attestation contract lives in exactly one place.

### Trust model

- Issuer trust loaded from `~/.lanyte/attest/trust.toml`, not
  runtime env. The trust file lives under the HOME-trusted-paths
  root so admin operations have a stable, file-permission-protected
  configuration target.
- `ctx_hash` is currently a reserved JWT claim with structurally
  enforced shape. Consumer-side runtime context matching against
  `ctx_hash` is a follow-on; the field is structurally future-safe
  for that lift.

### Crypto + key handling

- Ed25519 signing via `seclusor-crypto v0.1.1` (`signing` feature),
  linked as a library — no shelling out, no PATH-resolution surface.
- Private signing material is age-encrypted at rest; only the public
  key sits in cleartext under the attest root.
- Memory hygiene via `zeroize` on private material lifetimes.

### License + governance

- Canonical MIT and Apache-2.0 license texts restored at repo root.
- Dependency license-policy baseline under `.goneat/dependencies.yaml`
  feeds the release-cycle `make license-check` gate.

## Release infrastructure

This release establishes the full manual-signing release flow used
across lanytehq Rust crates:

- **`Makefile`** — build / check / install + the canonical
  release-cycle targets (`release-prep`, `release-preflight`,
  `release-sign`, `release-verify`, `release-upload`,
  `release-undraft`, `release-upload-all`, `release-notes`,
  `version-check`, version bump verbs).
- **`scripts/`** — sign, verify, generate-checksums, upload,
  download, export-keys, verify-public-keys helpers consumed by the
  Make targets above.
- **`RELEASE_CHECKLIST.md`** — canonical end-to-end procedure
  including external-adopter verification commands.
- **`SECURITY.md`** — issuer-side trust posture (key handling, JWT
  verification, supported versions, reporting path).
- **`CONTRIBUTING.md`** — PR workflow, agent attribution format,
  MSRV policy.
- **`keys/expected-fingerprints.txt`** — TBD placeholder until the
  lanytehq release-signing keypair is provisioned.

## Upgrade Notes

First release — no upgrade path. New install:

```bash
cargo install --git https://github.com/lanytehq/lanyte-attest --tag v0.1.0
```

Or from a local checkout:

```bash
git clone https://github.com/lanytehq/lanyte-attest
cd lanyte-attest
git checkout v0.1.0
make install   # installs to ~/.local/bin/lanyte-attest
```

First-time setup:

```bash
lanyte-attest keygen --issuer <instance-name>
# Generates ~/.lanyte/attest/signing-key.pub + signing-key.age
# Writes ~/.lanyte/attest/trust.toml with this issuer trusted
```
